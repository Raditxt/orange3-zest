# Extra Trees paling siap dibuktikan dari Orange

Dari lima kandidat, hanya **A (Extra Trees, Geurts 2006)** yang punya implementasi rujukan langsung di Python bawaan Orange 3.40, yaitu `sklearn.ensemble.ExtraTreesClassifier`. Kelas ini mengutip paper Geurts dan mengikuti mekanisme acaknya, tetapi **fungsi skornya berbeda**. Sklearn memakai Gini/entropy, sedangkan paper memakai normalized information gain 2·I/(H_s+H_c). **E (multi-label tree)** punya padanan parsial tanpa instal tambahan: `DecisionTreeClassifier` dengan y multi-output dan `criterion="entropy"` setara dengan entropi ML-C4.5 *sebagai impurity node*, tetapi algoritmanya secara keseluruhan bukan ML-C4.5. **D (C4.5)** tidak ada di sklearn, yang memakai CART. Rujukan setianya adalah Weka J48 atau kode C R8 Quinlan, dan keduanya butuh Java atau C di luar Orange. **C (UDT, Tsang dkk.)** tidak punya implementasi Python, tetapi papernya paling mudah direplikasi angkanya: dataset UCI, protokol ketidakpastian dirinci, akurasi dilaporkan, dan kode Java pernah dirilis. **B (Extension Decision Tree berbasis extenics)** tidak punya kode, dataset publik, maupun angka akurasi, sehingga tidak bisa dibuktikan terhadap rujukan. Penanda **[belum terverifikasi]** menandai temuan yang belum dicek ke sumber primer atau masih berasal dari ringkasan model atas PDF.

Versi acuan: Orange 3.40.0 mensyaratkan `scikit-learn>=1.5.1` ([requirements-core.txt @3.40.0](https://github.com/biolab/orange3/blob/3.40.0/requirements-core.txt)). Pengecekan kode sumber dilakukan pada tag sklearn 1.5.2. Versi persis sklearn di installer Windows Orange 3.40.0 **[belum terverifikasi]**. Cek dengan `import sklearn; print(sklearn.__version__)` di widget Python Script.

## A. Extra Trees: rujukan tersedia, fungsi skor berbeda

| Aspek | Temuan |
|---|---|
| Paper acuan | Geurts, Ernst, Wehenkel, "Extremely randomized trees", *Machine Learning* 63(1):3–42, 2006 ([dblp](https://dblp.dagstuhl.de/rec/journals/ml/GeurtsEW06.html)) |
| Bisa dipanggil dari Python Orange 3.40? | **Ya, tanpa instal tambahan.** `sklearn.ensemble.ExtraTreesClassifier` dan `sklearn.tree.ExtraTreeClassifier` ada di 1.5 dan mengutip Geurts 2006 ([sklearn 1.5](https://scikit-learn.org/1.5/modules/generated/sklearn.ensemble.ExtraTreesClassifier.html)) |
| Di Orange sendiri | Tidak ada learner/widget Extra Trees di 3.40.0. Pola `RandomForestLearner` (`__wraps__ = RandomForestClassifier`) bisa ditiru dengan sedikit kode ([random_forest.py](https://github.com/biolab/orange3/blob/3.40.0/Orange/classification/random_forest.py)) |
| Yang sama dengan paper | Untuk setiap fitur kandidat, satu threshold diambil uniform di [min, max] node ([_splitter.pyx 1.5.2](https://github.com/scikit-learn/scikit-learn/blob/1.5.2/sklearn/tree/_splitter.pyx)). Tanpa bootstrap (`bootstrap=False`). K=sqrt(n) dan n_min=2 untuk klasifikasi. M=100 ([Geurts 2006](https://www.personal.soton.ac.uk/cz1y20/Reading_Group/mlts-2024s/week10/Extremely_randomized_trees.pdf)) |
| Yang berbeda | (1) **Skor split:** sklearn memakai gini/entropy/log_loss, paper memakai 2·I/(H_s+H_c). Pembagian dengan H_s bisa mengubah urutan kandidat split. (2) Pembulatan K: sklearn memakai floor, paper "rounded" **[belum terverifikasi]**. (3) Fitur konstan ditangani sedikit berbeda. (4) Split subset acak untuk atribut nominal dari paper tidak tersedia, sehingga Orange melakukan encoding. (5) NaN tidak didukung splitter `random` di 1.5.2 ([_classes.py](https://github.com/scikit-learn/scikit-learn/blob/1.5.2/sklearn/tree/_classes.py)), jadi perlu imputasi. Paper juga membuang dataset bermissing value |
| Dataset & angka | 12 dataset klasifikasi (mayoritas UCI: Vehicle, Vowel, Segment, Spambase, Satellite, Pendigits, Letter, Isolet, plus generator Waveform/Two-Norm/Ring-Norm) dengan ukuran LS/TS tetap. Split diulang 10 kali (50 kali untuk dataset kecil) ([Geurts 2006](https://www.personal.soton.ac.uk/cz1y20/Reading_Group/mlts-2024s/week10/Extremely_randomized_trees.pdf)). Contoh error ETd: Waveform 16,61%, Letter 3,80%, Isolet 7,61% **[belum terverifikasi; dari ringkasan PDF]** |
| Bisa direplikasi? | **Ya, secara statistik** (dalam kisaran ±1 SD). Tidak bisa sampai desimal karena seed tidak dipublikasikan. Dig44 mungkin tidak publik |
| Kesetaraan sklearn vs paper | **"Mendekati bila dikonfigurasi", bukan identik.** Kesetaraan persis butuh kriteria kustom (Cython) atau reimplementasi skor paper di Python |

## B. Extension Decision Tree: tidak ada yang bisa dicocokkan

| Aspek | Temuan |
|---|---|
| Paper acuan | Teori extenics: Cai Wen, "Extension theory and its application", *Chinese Science Bulletin* 44(17), 1999 ([Springer](https://link.springer.com/content/pdf/10.1007/BF02886090.pdf)). Algoritma EDT: Lu & Wang, *JESA* 52(6):559–567, 2019 ([IIETA](https://iieta.org/download/file/fid/23278)). Ada pula Wang, Xu, Li, ICMSE 2018 ([Atlantis](https://www.atlantis-press.com/article/25895110.pdf)). Tidak ada satu paper kanonik |
| Isi algoritma | Model matter-element, dependent function untuk klasifikasi/diskretisasi, **pohon ID3 (information gain) biasa**, lalu extension transform diterapkan pada aturan hasil pelatihan |
| Implementasi di Python Orange 3.40 | **Tidak ada.** Sklearn tidak punya padanan. Emulasi yang mungkin: diskretisasi dengan dependent function K(x), lalu `DecisionTreeClassifier(criterion="entropy")` atau `TreeLearner` Orange. Ini inferensi, bukan metode yang dipublikasikan |
| Implementasi rujukan lain | **Tidak ditemukan** (pencarian GitHub belum menyeluruh) |
| Dataset & angka | Lu & Wang: 200 kasus dari database internal, tidak dirilis, tanpa metrik akurasi. ICMSE 2018: contoh mainan 10 lansia, hanya nilai information gain. Paper GDUT 2019 berbahasa Tiongkok belum dibaca **[belum terverifikasi]** |
| Bisa direplikasi? | **Tidak.** Paling jauh hanya pengecekan perilaku, misalnya mencocokkan nilai gain pada tabel contoh |
| Kesetaraan | Tidak ada rujukan untuk dibandingkan |

## C. UDT Tsang dkk.: paper paling replikabel, kode hanya Java

| Aspek | Temuan |
|---|---|
| Paper acuan | Tsang, Kao, Yip, Ho, Lee, "Decision Trees for Uncertain Data", *IEEE TKDE* 23(1), 2011 ([HKU PDF](https://repository.hku.hk/bitstream/10722/152447/1/Content.pdf)). Alternatif: DTU, Qin dkk., PAKDD 2009 ([Crossref](https://api.crossref.org/works/10.1007%2F978-3-642-01307-2_4)), belum dicek |
| Implementasi di Python Orange 3.40 | **Tidak ada.** Sklearn tidak punya padanan. Pendekatan `sample_weight` dengan ekspansi s titik berbobot hanyalah aproksimasi, bukan pencarian split atas interval pdf ala UDT (inferensi) |
| Implementasi rujukan lain | Kode Java (JDK 1.6) dari penulis di `cs.hku.hk/~dbgroup/UDT/`. **URL tidak bisa diakses dan lisensinya tidak disebut [belum terverifikasi]** ([HKU PDF](https://repository.hku.hk/bitstream/10722/152447/1/Content.pdf)). `pyuid3` (Apache-2.0) mengimplementasikan **paper lain**, dan API-nya tidak kompatibel dengan sklearn ([GitHub](https://github.com/sbobek/pyuid3)) |
| Dataset & protokol | 10 dataset UCI (Iris, Ionosphere, Segment, Vehicle, Satellite, PenDigits, BreastCancer, JapaneseVowel, dll.). Ketidakpastian disuntikkan dengan interval selebar w × rentang atribut, Gaussian σ = lebar/4 (uniform juga diuji), s=100 titik sampel ([HKU PDF](https://repository.hku.hk/bitstream/10722/152447/1/Content.pdf)) |
| Angka | AVG vs UDT: JapaneseVowel 81,89% → 87,30%. Iris 94,73% → 96,13% pada w terbaik. Tabel 2 dan 3 lengkap belum diekstrak **[belum terverifikasi]** |
| Bisa direplikasi? | **Ya.** Data publik dan protokol rinci, sehingga reimplementasi NumPy bisa dicek terhadap Tabel 3 (minimal Iris dan JapaneseVowel). Jika kode Java masih ada, kode itu bisa dipakai sebagai oracle lewat subprocess |
| Kesetaraan | Tidak ada padanan sklearn. Bukti kebenaran harus datang dari angka paper atau kode Java penulis |

## D. C4.5: sklearn bukan C4.5, J48 menjadi oracle

| Aspek | Temuan |
|---|---|
| Paper acuan | Quinlan, *C4.5: Programs for Machine Learning*, 1993. Release 8: "Improved Use of Continuous Attributes in C4.5", JAIR 1996 ([arXiv](https://arxiv.org/abs/cs/9603103)) |
| Implementasi di Python Orange 3.40 | **Tidak ada.** Dokumentasi sklearn menyatakan sklearn memakai CART teroptimasi ([sklearn 1.5 §1.10.6](https://scikit-learn.org/1.5/modules/tree.html)). `TreeLearner` Orange lebih dekat (split multiway nominal, penalti missing value), tetapi memakai gain biasa tanpa gain ratio dan tanpa post-pruning ([tree.py @3.40.0](https://github.com/biolab/orange3/blob/3.40.0/Orange/classification/tree.py)) |
| Perbedaan sklearn vs C4.5 | Gini/gain sebagai pengganti gain ratio. Split selalu biner. Tanpa dukungan kategorikal. `ccp_alpha` sebagai pengganti pruning pesimistis CF=0,25 dan subtree raising. NaN dikirim ke satu sisi, bukan instance fraksional. Tanpa koreksi MDL |
| Implementasi rujukan lain | **Weka J48:** "pruned or unpruned C4.5". Default CF=0,25, M=2, subtree raising aktif, koreksi MDL aktif. Memakai gain ratio dan missing value fraksional ([J48.java](https://github.com/Waikato/weka-3.8/blob/master/weka/src/main/java/weka/classifiers/trees/J48.java), [C45Split.java](https://github.com/Waikato/weka-3.8/blob/master/weka/src/main/java/weka/classifiers/trees/j48/C45Split.java)). Dari Python: `python-weka-wrapper3` 0.3.3 (Weka 3.9.7, JPype) ([PyPI](https://pypi.org/project/python-weka-wrapper3/)), **butuh JDK** dengan bitness yang sama ([install](https://fracpete.github.io/python-weka-wrapper3/install.html)). **Kode C R8 Quinlan** beredar di mirror akademik, lisensinya belum dicek. `chefboost` (MIT) tidak terbukti punya pruning atau missing value ala C4.5 ([GitHub](https://github.com/serengil/chefboost)) |
| Dataset & angka | Daftar dataset dan akurasi Quinlan 1993/1996 **belum diambil**. Dataset UCI yang menguji missing value (breast-cancer, hepatitis, vote, dll.) **[belum terverifikasi; pengetahuan umum]** |
| Bisa direplikasi? | Lebih kuat lewat **J48 sebagai oracle pada split yang identik** (bandingkan ukuran pohon dan error) daripada lewat angka paper lama |
| Kesetaraan | Klaim bahwa J48 dibangun dari C4.5 R8 lazim ditemui, tetapi sumber primernya belum diambil **[belum terverifikasi]** |

## E. ML-C4.5: impurity setara di sklearn, algoritma tidak

| Aspek | Temuan |
|---|---|
| Paper acuan | Clare & King, PKDD 2001, LNCS 2168. Entropi multi-label −Σ[p log p + q log q]. Daun berisi himpunan label ([Springer PDF](https://link.springer.com/content/pdf/10.1007/3-540-44794-6_4.pdf)) |
| Implementasi di Python Orange 3.40 | **Parsial, tanpa instal tambahan.** `DecisionTreeClassifier` menerima y 2D. Kode `Entropy.node_impurity` di 1.5.2 menghasilkan rata-rata entropi per output, yaitu entropi ML-C4.5 dibagi konstanta L ([_criterion.pyx 1.5.2](https://raw.githubusercontent.com/scikit-learn/scikit-learn/1.5.2/sklearn/tree/_criterion.pyx)). Uji sendiri pada 300 dataset sintetis: split stump sama di **298/300** kasus dengan bobot jumlah instance, tetapi hanya **261/300** dengan bobot "dihitung dua kali" ala Clare & King. Uji dijalankan dengan sklearn 1.9.1, bukan 1.5.2, dan belum dipublikasikan |
| Hambatan di Orange | `TreeLearner` dan `SklTreeLearner` tidak menyetel `supports_multiclass`, sehingga data multi-target memicu `TypeError` ([base.py @3.40.0](https://raw.githubusercontent.com/biolab/orange3/3.40.0/Orange/base.py)). Add-on perlu Learner sendiri dan kemungkinan viewer khusus |
| Implementasi rujukan lain | **Kode C asli Clare** (patch atas C4.5 R8), dari Aberystwyth, lisensi tidak disebut ([Aberystwyth](https://www.aber.ac.uk/en/cs/research/cb/dss/c45modifications/)). **MEKA** tidak mencantumkan ML-C4.5 ([MEKA](https://waikato.github.io/meka/methods)). **Mulan**: menurut Madjarov 2012, ML-C4.5 dijalankan lewat Mulan, tetapi halaman Mulan tidak mencantumkannya **[belum terverifikasi]**. **scikit-multilearn** 0.2.0 terakhir rilis 2018 ([PyPI](https://pypi.org/project/scikit-multilearn/)). Fork **-ng** 0.0.8 (2024) hanya menyediakan transformasi masalah, bukan pohon multi-label tunggal ([PyPI](https://pypi.org/project/scikit-multilearn-ng/)). **pyclus** 1.0.2 membungkus PCT CLUS, API ala sklearn, **butuh Java** ([PyPI](https://pypi.org/project/pyclus)). Kompatibilitas keduanya dengan sklearn 1.5.x belum diuji |
| Dataset & angka | Clare & King memakai data fenotipe ragi milik sendiri dan mengevaluasi akurasi aturan (m-estimate, bootstrap), jadi tidak ada angka benchmark utama. **Madjarov dkk. 2012** menguji ML-C4.5 dan PCT pada 11 dataset Mulan dengan split tetap. Contoh: Hamming loss emotions ML-C4.5 0,247, PCT 0,267 **[belum terverifikasi; dari ringkasan PDF]** ([Madjarov 2012](https://repository.ukim.mk:443/bitstream/20.500.12188/17147/1/PR_2012.pdf), [dataset Mulan](https://mulan.sourceforge.net/datasets-mlc.html)) |
| Bisa direplikasi? | Ya, terhadap Madjarov pada emotions/yeast/scene (fitur numerik). Kecocokan tidak akan persis dengan sklearn karena pruning dan detail C4.5 berbeda. Yeast Mulan ≠ data ragi Clare & King |
| Kesetaraan | "Setara **sebagai impurity node**, sklearn **bukan** ML-C4.5." Pemakaian gain atau gain ratio di ML-C4.5 dan aturan pelabelan daunnya **[belum terverifikasi]** (cek tesis Clare 2003) |

## Widget Python Script menerima learner, bukan estimator sklearn mentah

Widget Python Script menyediakan `in_data`, `in_learner`, `in_classifier`, `in_object` beserta bentuk jamak `in_datas` dan seterusnya (semua MultiInput), lalu membaca `out_data`, `out_learner`, `out_classifier`, `out_object`. **`out_learner` harus instance `Orange.base.Learner`.** Jika tipenya salah, widget memunculkan error dan mengirim None ([owpythonscript.py, master](https://raw.githubusercontent.com/biolab/orange3/master/Orange/widgets/data/owpythonscript.py); [dokumentasi](https://orange3.readthedocs.io/projects/orange-visual-programming/en/latest/widgets/data/pythonscript.html)). Karena itu, estimator sklearn harus dibungkus. Untuk A dan E-parsial: subclass `SklLearner` dengan `__wraps__` ([base_classification.py @3.40.0](https://raw.githubusercontent.com/biolab/orange3/3.40.0/Orange/classification/base_classification.py)). Untuk B, C, dan D versi kustom: subclass `Learner` dengan `fit(X, Y, W)` yang mengembalikan `Model.predict(X)`. Learner hasilnya bisa disambungkan ke Test and Score. Tiga hal **[belum terverifikasi]**: kode widget yang dibaca berasal dari master, bukan tag 3.40.0; jalur re-export `Orange.classification.SklLearner`; dan risiko pickling untuk kelas yang didefinisikan di dalam skrip. Untuk add-on, letakkan kelas di modul yang bisa diimpor. Paket tambahan (pww3, pyclus, uid3, JPype) tidak dibundel dan harus dipasang dengan pip ke Python Orange. Java tetap harus dipasang terpisah.

## Implikasi untuk pemilihan: urutan berdasarkan keterverifikasian

| Peringkat | Kandidat | Bukti terkuat yang tersedia | Biaya/risiko |
|---|---|---|---|
| 1 | **A Extra Trees** | Paper + implementasi rujukan yang mengutip paper, di dalam Orange tanpa instal tambahan + dataset UCI publik | Selisih fungsi skor harus didokumentasikan (atau skor paper diimplementasikan). Replikasi hanya statistik |
| 2 | **E ML-C4.5** | Paper + benchmark replikabel (Madjarov/Mulan) + kesetaraan impurity di sklearn (terbukti dari kode) | Algoritma penuh tidak ada di Python. Butuh `supports_multiclass` dan viewer baru. Oracle penuh (C asli, Mulan, pyclus) butuh C atau Java |
| 3 | **D C4.5** | Paper + oracle kuat (J48/R8) | Oracle hanya bisa diakses lewat JDK + pww3 atau C. Sklearn dan Orange `TreeLearner` bukan C4.5 |
| 4 | **C UDT** | Paper + dataset UCI + protokol rinci + angka | Tidak ada implementasi yang bisa dipanggil. Kode Java penulis belum tentu masih tersedia. Bukti kebenaran bertumpu pada pencocokan angka |
| 5 | **B Extension DT** | Hanya paper aplikasi | Tanpa kode, data publik, maupun angka, sehingga tidak memenuhi standar "paper + implementasi rujukan" |

Jika kriterianya "paper + implementasi rujukan" yang bisa dijalankan di dalam Orange hari ini, **A adalah satu-satunya yang langsung memenuhi syarat**. Klaim kesetaraannya harus jujur: konfigurasi sklearn setia pada mekanisme acak Geurts, tetapi memakai kriteria impurity standar. Ada dua jalan. Pertama, menerima selisih ini dan memvalidasi angka paper dalam batas ±SD. Kedua, menambahkan skor 2·I/(H_s+H_c) versi Python dan memakai `ExtraTreesClassifier(criterion="entropy")` sebagai pembanding. Jalan kedua justru memberi widget kontribusi yang bisa dibuktikan terhadap dua rujukan sekaligus. E adalah pilihan kedua yang menarik jika "Extended" dimaknai sebagai perluasan ke multi-label, tetapi beban integrasi multi-target di Orange cukup besar. C sebaiknya dijadikan kandidat lanjutan setelah ketersediaan kode Java HKU dipastikan. Sebelum mengutip angka di dokumen resmi, periksa dulu langsung ke PDF: Tabel 8 Geurts, Tabel 3 Tsang, Tabel B1 Madjarov, dan Bagian 4.3 Madjarov (apakah ML-C4.5 benar dijalankan lewat Mulan).
